## Key Terms

1. **Compile-Time Checked Query**: SQL validated at compile time via query! macro.
2. **FromRow**: A derive macro for mapping query results to structs.
3. **Migration**: A versioned SQL script for schema changes.
4. **Connection Pool**: A pool of database connections for concurrent access.
5. **Transaction**: A group of operations executed atomically.
6. **QueryBuilder**: A builder for constructing dynamic SQL queries.
7. **Offline Mode**: Pre-validating SQL queries without a running database.
8. **Prepare**: The act of sending a SQL query to the database for parsing and planning.
9. **Savepoint**: A named point within a transaction for partial rollback.
10. **ENUM Type**: A PostgreSQL custom enum mapped to a Rust enum.
11. **JSONB**: PostgreSQL binary JSON column type.
12. **Array Type**: PostgreSQL array column type.
13. **Connection String**: The URL or string used to connect to a database.
14. **Migration Directory**: The directory (migrations/) containing SQL migration files.
15. **SQLx Data JSON**: The file (sqlx-data.json) containing prepared query metadata for offline mode.

## Architecture Notes

SQLx is an async, pure-Rust SQL framework. It connects to databases using the Tokio async runtime. The query! macros use a DATABASE_URL environment variable at compile time to connect to a database and verify SQL syntax and types. Offline mode uses a prepared JSON file (generated by `cargo sqlx prepare`) that stores query metadata. Connection pools are created with `PgPoolOptions`, `MySqlPoolOptions`, or `SqlitePoolOptions`.

## Key APIs

- `sqlx::PgPool`, `sqlx::MySqlPool`, `sqlx::SqlitePool` — pool types
- `sqlx::query!("SELECT ...")` — compile-time checked query
- `sqlx::query_as::<_, MyStruct>("SELECT ...")` — typed query result
- `sqlx::query_scalar!("SELECT ...")` — single-column query
- `sqlx::types::{Uuid, Json, Chrono, Decimal}` — custom type support
- `sqlx::migrate!("migrations/...")` — runtime migration execution
- `sqlx::Transaction<'_, DB>` — transaction type
- `sqlx::QueryBuilder` — dynamic query construction
- `sqlx::Error` — comprehensive error type

## Conventions

- Migration files: `YYYYMMDD_description.sql` (up) and `YYYYMMDD_description.down.sql` (down)
- Row structs: named after the table, PascalCase, with same field names as columns
- Connection URL: stored in DATABASE_URL environment variable or `.env` file
- Queries: inline with query! macro for static, QueryBuilder for dynamic
- Module structure: separate `db/` module or per-resource modules
